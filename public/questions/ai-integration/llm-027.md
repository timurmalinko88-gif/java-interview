# Streaming Responses with Server-Sent Events (SSE) & Backpressure

Как реализовать потоковую передачу ответа модели пользователю через Server-Sent Events (SSE) в Spring Boot? Какие сложности возникают со стримингом при вызове Tools?

---ANSWER---

### Короткий ответ
Контроллер возвращает SseEmitter или Flux<ServerSentEvent<String>>. Провайдер стримит дельты токенов в формате data: {...} по протоколу chunked transfer. Сложность с Tools: если модель решила вызвать инструмент, стримить клиенту нечего (передаются сырые фрагменты JSON аргументов инструмента), пока бэкенд не выполнит инструмент и не получит финальный текст ответа.

### Подробное объяснение
Генерация ответа на 500 токенов занимает ~15 секунд. Если ждать полного ответа, пользователь видит 'зависший' спиннер. Streaming позволяет отдавать токены по мере их генерации, снижая воспринимаемую задержку (Perceived Latency) до 500 мс.

### Реализация в Spring Boot Controller:
```java
@GetMapping(value = "/api/ai/stream", produces = MediaType.TEXT_EVENT_STREAM_VALUE)
public Flux<String> streamChat(@RequestParam String message) {
    return assistantStreamingService.streamChat(message)
            .timeout(Duration.ofSeconds(60))
            .onErrorResume(e -> Flux.just("[Ошибка генерации ответа: " + e.getMessage() + "]"));
}
```

### Дилемма Streaming + Tool Calling:
1. **Обычный ответ**: токены немедленно транслируются клиенту в SSE-канал (chunk -> sse.send(chunk)).
2. **Вызов инструмента (Tool Calling)**:
   - Модель начинает стримить фрагменты JSON-вызова: delta: {name: "getServiceStatus", arguments: "{\"serv"}.
   - **Этот JSON нельзя стримить пользователю в окно чата!** Пользователь не должен видеть технический код вызова функции.
   - Backend обязан перехватить поток, собрать полный JSON аргументов в буфер, выполнить Java-метод и отправить новый запрос провайдеру, переключившись на стриминг финального текста.

### Уточняющий вопрос на интервью (Follow-up)
Что произойдет с соединением SseEmitter, если пользователь закроет вкладку браузера на 5-й секунде стриминга? Как корректно отменить HTTP-запрос к провайдеру?

### Распространённый неверный ответ (Pitfall)
Транслировать в SSE-поток пользователю сырые служебные чанки с вызовами tool_calls и JSON-аргументами.

### Key Points
- SSE снижает perceived latency с 15-30 секунд до 500 мс.
- Используйте Flux<String> или SseEmitter в Spring Boot контроллерах.
- Служебные чанки вызова инструментов должны буферизоваться внутри бэкенда.
- Обязательно обрабатывайте отключение клиента (onCompletion, onTimeout) для отмены запроса к LLM.

### Life Analogy
Телетрансляция спортивного матча в прямом эфире (Streaming) вместо ожидания публикации газеты с результатами игры на следующее утро.
