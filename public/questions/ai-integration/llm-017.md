# Context Truncation & Preserving Tool Call-Result Pairs

Как правильно сокращать историю диалога при приближении к лимиту контекстного окна, не разрушая строгую связь пар tool_calls и tool results?

---ANSWER---

### Короткий ответ
Нельзя просто отрезать первые N сообщений или удалять сообщения по одному. В протоколе OpenAI/Anthropic за каждым сообщением ассистента с tool_calls ОБЯЗАТЕЛЬНО должны следовать сообщения с ролью tool для каждого tool_call_id. Разрыв этой связки вызовет фатальную ошибку HTTP 400 Invalid request: missing tool response. Обрезка должна выполняться атомарными блоками диалога.

### Подробное объяснение
Когда диалог длится долго, массив messages вырастает и рискует превысить лимит токенов.

### Опасная ошибка:
Наивный алгоритм удаляет старейшие сообщения: messages.remove(0);
Если удалилось сообщение ассистента с tool_calls, но осталось сообщение с ролью tool, API вернет:
HTTP 400: 'messages': Expected tool response to be preceded by assistant message with tool_calls.
Если удалить tool результат, но оставить tool_calls, API вернет:
HTTP 400: Tool call with id 'call_123' was not answered.

### Безопасный алгоритм усечения истории (Atomic Turn Truncation):
1. Системное сообщение (role: system) **никогда не удаляется** (всегда индекс 0).
2. Диалог разбивается на атомарные логические раунды (Turn):
   - Обычный раунд: User -> Assistant
   - Инструментальный раунд: User -> Assistant (tool_calls) -> Tool results -> Assistant (final answer)
3. При превышении бюджета усекаются только старейшие полные раунды целиком.

```java
public void pruneHistorySafely(List<ChatMessage> history, int maxAllowedMessages) {
    if (history.size() <= maxAllowedMessages) return;

    ChatMessage systemPrompt = history.get(0);
    List<ChatMessage> conversation = new ArrayList<>(history.subList(1, history.size()));

    while (conversation.size() > maxAllowedMessages) {
        int nextUserIdx = 1;
        while (nextUserIdx < conversation.size() && !"user".equals(conversation.get(nextUserIdx).role())) {
            nextUserIdx++;
        }
        conversation.subList(0, nextUserIdx).clear();
    }

    history.clear();
    history.add(systemPrompt);
    history.addAll(conversation);
}
```

### Уточняющий вопрос на интервью (Follow-up)
Что лучше: удалить старые сообщения целиком или сжать их в одно саммари-сообщение (Summarization)?

### Распространённый неверный ответ (Pitfall)
Удалять сообщения из истории по количеству элементов списка без учета парной связки tool_calls и tool_call_id.

### Key Points
- Каждое сообщение ассистента с tool_calls жестко связано со следующими сообщениями tool.
- Нарушение структуры связки приводит к ошибке валидации API 400.
- Системный промпт всегда сохраняется в начале истории.
- Удаление должно производиться целыми законченными раундами (Turns).

### Life Analogy
В юридическом договоре нельзя вырвать страницу с вопросом аудитора, оставив приложение с ответом бухгалтера. Без контекста вопроса сам ответ юридически недействителен и ломает всё делопроизводство.
