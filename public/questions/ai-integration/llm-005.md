# Spring Boot LLM Client Architecture

Как спроектировать архитектуру взаимодействия с LLM в Spring Boot приложении с четким разделением слоев (Controller, Service, Provider Client) и DTO?

---ANSWER---

### Короткий ответ
Контроллер принимает клиентский запрос и валидирует входные данные; сервис инкапсулирует бизнес-логику (сборку контекста, выбор системного промпта, лимиты); отдельный Provider Client отвечает за HTTP-транспорт, сериализацию, авторизацию через заголовок и обработку HTTP-статусов.

### Подробное объяснение
Смешивание HTTP-вызовов к OpenAI с бизнес-логикой контроллера — антипаттерн, приводящий к невозможности тестирования и смене провайдера.

### Чистая архитектура слоев:
1. ChatController: @PostMapping("/api/ai/chat"), принимает ChatUserRequest, валидирует @Valid, возвращает ChatUserResponse.
2. AssistantService: получает ID пользователя, достает историю сессии, обогащает системным промптом, вызывает LlmClient, сохраняет результат.
3. LlmClient (например, OpenAiCompatibleClient): чистый HTTP-клиент (на базе java.net.http.HttpClient или RestClient), не знающий о пользователях приложения. Знает только о model, messages, temperature и API-ключах.

### Пример реализации LlmClient:
```java
@Component
public class OpenAiCompatibleClient {
    private final HttpClient httpClient;
    private final ObjectMapper objectMapper;
    private final String apiKey;
    private final String baseUrl;

    public OpenAiCompatibleClient(
            @Value("${llm.api-key}") String apiKey,
            @Value("${llm.base-url:https://api.openai.com/v1}") String baseUrl,
            ObjectMapper objectMapper) {
        this.apiKey = apiKey;
        this.baseUrl = baseUrl;
        this.objectMapper = objectMapper;
        this.httpClient = HttpClient.newBuilder()
                .connectTimeout(Duration.ofSeconds(10))
                .build();
    }

    public ChatCompletionResponse sendChat(ChatCompletionRequest request) throws IOException, InterruptedException {
        String body = objectMapper.writeValueAsString(request);
        HttpRequest httpRequest = HttpRequest.newBuilder()
                .uri(URI.create(baseUrl + "/chat/completions"))
                .header("Authorization", "Bearer " + apiKey)
                .header("Content-Type", "application/json")
                .timeout(Duration.ofSeconds(60))
                .POST(HttpRequest.BodyPublishers.ofString(body))
                .build();

        HttpResponse<String> response = httpClient.send(httpRequest, HttpResponse.BodyHandlers.ofString());
        if (response.statusCode() >= 400) {
            throw new LlmApiException(response.statusCode(), response.body());
        }
        return objectMapper.readValue(response.body(), ChatCompletionResponse.class);
    }
}
```

### Уточняющий вопрос на интервью (Follow-up)
Почему HttpClient создается один раз в Spring-бине, а не создается заново на каждый входящий запрос пользователя?

### Распространённый неверный ответ (Pitfall)
Хранить API-ключ в коде или внедрять HTTP-вызовы напрямую в @RestController без изоляции в сервисном слое.

### Key Points
- Четкое разделение: Controller (REST) -> Service (Оркестрация) -> Client (HTTP).
- API-ключи передаются исключительно через переменные окружения (@Value).
- Отдельные DTO для внешнего API приложения и для внутреннего LLM-протокола.
- Таймауты клиента настраиваются с учетом специфики генерации текста.

### Life Analogy
Ресторан: Контроллер — это официант (принимает заказ от гостя). Сервис — это шеф-повар (компонует блюдо и ингредиенты). Клиент провайдера — это закупщик на оптовой базе (доставляет ингредиенты по стандартизированному накладным протоколу).
