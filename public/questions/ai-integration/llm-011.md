# Handling Unknown Tools, Invalid Arguments & Schema Drift

Как обрабатывать ситуации, когда модель возвращает неизвестное имя tool, битый JSON в аргументах или аргументы, не соответствующие схеме?

---ANSWER---

### Короткий ответ
Не падать с необработанным исключением. Вместо этого сериализовать ошибку валидации в читаемый JSON-ответ с описанием проблемы и вернуть его в сообщении с ролью tool. Модель использует это сообщение для самокоррекции (Self-Correction) и повторит вызов с исправленными аргументами.

### Подробное объяснение
При активном вызове инструментов модель может ошибиться:
1. Придумать несуществующий инструмент (getTicketDetails вместо getDemoTicket).
2. Оборвать строку JSON-аргументов из-за нехватки токенов ({"ticketId": "TCK-).
3. Передать строку вместо числа или пропустить обязательное поле.

Если Java-код выбросит JsonProcessingException и прервет запрос кодом 500, пользователь получит сломанный интерфейс.

### Паттерн самокоррекции модели (Self-Correction):
```java
public String executeWithSafeFallback(String toolName, String jsonArgs, ToolRegistry registry) {
    try {
        AssistantTool tool = registry.getTool(toolName);
        if (tool == null) {
            return "{"status": "error", "message": "Tool '" + toolName + "' does not exist. Available tools: " + registry.getAvailableNames() + ""}";
        }
        
        JsonNode argsNode = objectMapper.readTree(jsonArgs);
        if (!argsNode.hasNonNull("ticketId")) {
            return "{"status": "error", "message": "Missing mandatory parameter 'ticketId'. Please provide a valid ticket ID like TCK-101."}";
        }
        
        return tool.execute(argsNode);
    } catch (JsonProcessingException e) {
        return "{"status": "error", "message": "Malformed JSON in arguments. Please re-generate arguments matching the JSON Schema."}";
    }
}
```
Получив ответ со статусом error и подсказкой, современные модели в 95% случаев успешно исправляют ошибку на следующем шаге цикла!

### Уточняющий вопрос на интервью (Follow-up)
Сколько попыток самокоррекции разумно давать модели перед принудительным завершением цикла?

### Распространённый неверный ответ (Pitfall)
Выбрасывать внутренний RuntimeException при ошибке парсинга аргументов модели, прерывая весь диалог вместо возврата ошибки в контекст модели.

### Key Points
- Битый JSON или неверные параметры — штатная ситуация в вероятностных моделях.
- Возврат понятной ошибки в role: tool позволяет модели скорректировать вызов.
- Всегда валидируйте наличие обязательных полей перед передачей в бизнес-логику.
- Ограничивайте количество итераций самокоррекции для предотвращения зацикливания.

### Life Analogy
Если диспетчер такси не расслышал номер дома, он не бросает трубку, а переспрашивает: 'Вы назвали дом 12Б, но на этой улице дома только с номерами 1-10. Уточните адрес'.
