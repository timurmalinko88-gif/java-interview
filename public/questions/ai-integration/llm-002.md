# ChatGPT Web UI vs LLM API Integration

В чем фундаментальное отличие работы с ChatGPT через веб-интерфейс от интеграции с LLM API в backend-сервисе на Java/Spring Boot?

---ANSWER---

### Короткий ответ
Веб-интерфейс ChatGPT — это готовое stateful-приложение с автоматическим хранением сессий, скрытыми системными инструкциями и подмешиванием метаданных. LLM API — это строго stateless REST API: каждый вызов изолирован, всю историю диалога backend обязан передавать заново в каждом запросе.

### Подробное объяснение
Многие начинающие разработчики полагают, что если отправить в API сообщение 'Привет, меня зовут Иван', а следующим запросом спросить 'Как меня зовут?', модель вспомнит имя. Это грубая ошибка.

### Ключевые различия:
1. **Stateless vs Stateful**: Модель на стороне провайдера не хранит сессий между HTTP-запросами. Вся память диалога реализуется на стороне Java Backend: мы обязаны сохранять историю в БД (Redis, PostgreSQL) и повторно передавать массив messages при каждом вызове.
2. **Роли сообщений (Roles)**:
   - system: задает поведение, ограничения, allowlist инструментов и формат ответа (не видна конечному пользователю).
   - user: реплика пользователя приложения.
   - assistant: предыдущие ответы модели.
   - tool: результат выполнения функции бэкендом.
3. **Параметры генерации**: В API разработчик напрямую управляет гиперпараметрами (temperature, top_p, seed, presence_penalty), контролируя уровень детерминизма.
4. **Безопасность**: Веб-интерфейс использует непрозрачные фильтры OpenAI. В API ответственность за безопасность (санитизация, валидация, rate limiting) лежит на разработчике сервиса.

### Java DTO запроса к API:
```java
public record ChatMessage(String role, String content) {}

public record ChatCompletionRequest(
    String model,
    List<ChatMessage> messages,
    Double temperature,
    Integer maxTokens
) {}
```

### Уточняющий вопрос на интервью (Follow-up)
Что произойдет с latency и стоимостью диалога, если просто накапливать все сообщения в массиве messages без очистки?

### Распространённый неверный ответ (Pitfall)
Полагать, что модель 'помнит' пользователя по session ID или IP-адресу, и не передавать предысторию диалога в теле запроса.

### Key Points
- LLM API полностью stateless: нет сессий и серверной памяти диалога.
- История диалога собирается бэкендом и передается в массиве messages.
- Роль system определяет контракт и правила поведения модели.
- Температура (temperature) регулирует степень стохастичности (0.0 — максимальный детерминизм).

### Life Analogy
Веб-чат — это телефонный разговор с другом (он помнит всё, что вы сказали 5 минут назад). API — это отправка официальных писем почтой: каждое новое письмо должно содержать преамбулу и копии предыдущих документов, иначе адресат ничего не поймет.
