# Multi-Tool Loops, Step Budgets & Recursion Guards

Как реализовать цикл обработки множественных Tool Calls в Spring Boot с жестким ограничением шагов (Step Budget), защитой от бесконечного цикла и таймаутом?

---ANSWER---

### Короткий ответ
Цикл while должен ограничиваться счетчиком итераций (обычно max 3-5 шагов), общим таймаутом операции и проверкой finish_reason != 'tool_calls'. Модель может вернуть несколько параллельных tool calls в одном ответе — все они должны быть выполнены и возвращены в массив сообщений с сохранением соответствия tool_call_id.

### Подробное объяснение
Когда ассистенту поручают сложную задачу (например, 'Проверь статус сервиса платежей и найди открытые тикеты по нему'), модели требуется выполнить несколько вызовов подряд.

### Риски неконтролируемого цикла:
- Модель зацикливается, вызывая один и тот же инструмент с одинаковыми параметрами.
- Превышение времени ожидания HTTP-соединения клиентом.
- Лавинообразный расход токенов и бюджета.

### Эталонный безопасный цикл в Spring Boot:
```java
@Service
public class AssistantLoopService {
    private static final int MAX_STEPS = 5;
    private final OpenAiClient client;
    private final ToolRegistry toolRegistry;

    public String runAssistantLoop(List<ChatMessage> conversation) {
        int steps = 0;
        long startTime = System.currentTimeMillis();
        long maxExecutionTimeMs = 45000; // 45 sec budget

        while (steps < MAX_STEPS) {
            if (System.currentTimeMillis() - startTime > maxExecutionTimeMs) {
                throw new LlmExecutionTimeoutException("Превышен общий лимит времени выполнения ассистента");
            }
            steps++;

            ChatResponse response = client.sendChat(conversation, toolRegistry.getToolDefinitions());
            ChatMessage assistantMsg = response.getChoice().getMessage();
            conversation.add(assistantMsg);

            if (assistantMsg.getToolCalls() == null || assistantMsg.getToolCalls().isEmpty()) {
                return assistantMsg.getContent();
            }

            for (ToolCall toolCall : assistantMsg.getToolCalls()) {
                String toolResult = toolRegistry.execute(toolCall.getName(), toolCall.getArguments());
                conversation.add(ChatMessage.toolResult(toolCall.getId(), toolResult));
            }
        }

        return "К сожалению, задача потребовала слишком много шагов. Пожалуйста, уточните запрос.";
    }
}
```

### Уточняющий вопрос на интервью (Follow-up)
Что делать, если модель в одном ответе вернула список из 3 независимых вызовов tool_calls? Можно ли выполнить их параллельно через CompletableFuture?

### Распространённый неверный ответ (Pitfall)
Писать цикл while (true) с единственным условием выхода по ответу модели, рискуя получить бесконечную рекурсию при галлюцинации модели.

### Key Points
- Обязательно задавать максимальное количество итераций (Step Budget, 3–5).
- Обязателен общий таймаут на всю цепочку вызовов.
- Отсутствие tool_calls — штатное завершение цикла выходом на финальный текст.
- Параллельные tool calls должны возвращаться отдельными tool-сообщениями.

### Life Analogy
Лимит шагов похож на баланс шагов в настольной игре. У вас есть 5 ходов, чтобы найти ответ в лабиринте. Если за 5 ходов выход не найден, партия прекращается, чтобы игрок не блуждал вечно.
