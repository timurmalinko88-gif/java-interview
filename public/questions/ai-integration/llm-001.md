# Tokens, Context Window & Latency in LLM APIs

Что такое токены (tokens), context window и output limit при вызове LLM API? Как они влияют на стоимость, latency и проектирование backend-сервиса на Java?

---ANSWER---

### Короткий ответ
Токен — базовая единица текста для LLM (~4 символа английского или ~1-2 символа русского текста). Context window — предельный лимит входных + выходных токенов за один запрос. Latency линейно зависит от числа генерируемых токенов (Time-To-First-Token + generation time per token). Стоимость взимается за 1k/1M входных и выходных токенов.

### Подробное объяснение
При проектировании интеграции с LLM в Java Backend критично понимать различия между обработкой обычных HTTP-запросов и вызовами языковых моделей:

1. **Токенизация (Tokenization)**: Текст разбивается на токены с помощью алгоритмов BPE (Byte-Pair Encoding). В кириллице один символ может кодироваться 2-3 токенами, что увеличивает расход бюджета контекста и стоимость в 2–3 раза по сравнению с английским.
2. **Context Window (Контекстное окно)**: Максимальный суммарный размер prompt_tokens + completion_tokens (например, 128k токенов у GPT-4o). Превышение вызывает HTTP 400 context_length_exceeded.
3. **Max Tokens (Output Limit)**: Параметр запроса max_tokens (или max_completion_tokens), ограничивающий длину генерируемого ответа. Защищает от бесконечной генерации и исчерпания финансового бюджета.
4. **Latency (Задержка)**:
   - **TTFT (Time-to-First-Token)**: время на чтение и токенизацию промпта моделью.
   - **Generation Time**: авторегрессионная генерация каждого последующего токена (~15-50 мс на токен). При запросе на 1000 выходных токенов задержка составит минимум 15–30 секунд!

### Java-пример расчета и защитных ограничений:
```java
public record LlmRequestBudget(int promptTokensEstimate, int maxCompletionTokens) {
    private static final int MAX_SAFE_TOTAL_TOKENS = 8192;

    public static LlmRequestBudget of(String prompt, int requestedOutputLimit) {
        // Эвристика: ~3 символа на токен для смешанного текста
        int estimatedPromptTokens = prompt.length() / 3;
        if (estimatedPromptTokens + requestedOutputLimit > MAX_SAFE_TOTAL_TOKENS) {
            throw new IllegalArgumentException("Запрос превышает безопасный лимит контекста!");
        }
        return new LlmRequestBudget(estimatedPromptTokens, requestedOutputLimit);
    }
}
```

### Уточняющий вопрос на интервью (Follow-up)
Как вы на собеседовании обоснуете выбор значения max_tokens и таймаута для HTTP-клиента в production-микросервисе?

### Распространённый неверный ответ (Pitfall)
Считать, что 1 токен равен 1 слову или 1 символу, и устанавливать стандартный HTTP таймаут в 2-3 секунды, из-за чего 90% запросов с генерацией длинного текста падают по SocketTimeoutException.

### Key Points
- Токен — это ~4 символа EN или 1-2 символа RU; вход и выход тарифицируются раздельно.
- Превышение Context Window приводит к фатальной ошибке HTTP 400.
- Генерация 1000 токенов занимает от 15 до 40 секунд; таймауты клиентов должны учитывать TTFT + время генерации.
- Ограничение max_tokens обязательно для защиты от неконтролируемых затрат.

### Life Analogy
Context window — это оперативная память калькулятора, а токены — байты. Если попытаться загрузить в буфер больше данных, чем физически помещается, вы получите переполнение стека.
