# Prompt Versioning & A/B Evaluation Harness

Как организовать версионирование промптов и harness для сравнения двух версий промптов на фиксированном наборе сценариев в Java?

---ANSWER---

### Короткий ответ
Промпты нельзя хардкодить строками в Java-коде. Их выносят в шаблоны с версионированием (например, в git репозитории или s3: support-prompt-v1.2.st), логируют версию промпта с каждым запросом и прогоняют обе версии через автоматизированный harness на фиксированном наборе golden-сценариев, фиксируя реальные метрики точности, а не субъективные впечатления.

### Подробное объяснение
Изменение даже одного слова в системном промпте может улучшить один кейс, но сломать три других (Prompt Regression).

### 1. Архитектура хранения:
- Шаблоны промптов хранятся в src/main/resources/prompts/ (например, с использованием шаблонизаторов StringTemplate, Jinja или Mustache).
- Каждый шаблон имеет семантическую версию и метаданные:
  ```properties
  prompt.version=2.1.0
  prompt.description=Added strict guidance on not disclosing internal IDs
  ```

### 2. Структура Evaluation Harness:
Создается тестовый стенд на JUnit 5, который на одном и том же наборе из 15 сценариев запускает две версии промпта и сравнивает результаты:

```java
public record EvalResult(String scenarioId, boolean toolMatched, boolean argsValid, int latencyMs) {}

@Test
void comparePromptVersions() {
    List<EvalScenario> scenarios = loadGoldenDataset();
    
    Map<String, EvalResult> resultsV1 = runHarness(promptV1, scenarios);
    Map<String, EvalResult> resultsV2 = runHarness(promptV2, scenarios);
    
    double accuracyV1 = calculateAccuracy(resultsV1);
    double accuracyV2 = calculateAccuracy(resultsV2);
    
    log.info("Prompt v1 Accuracy: {}%, Prompt v2 Accuracy: {}%", accuracyV1, accuracyV2);
    assertTrue(accuracyV2 >= accuracyV1, "Новая версия промпта ухудшила качество (регрессия)!");
}
```

### Уточняющий вопрос на интервью (Follow-up)
Почему при A/B тестировании промптов критично фиксировать параметр seed и выставлять temperature: 0.0?

### Распространённый неверный ответ (Pitfall)
Править системный промпт прямо в коде сервиса в production без прогона по регрессионному набору тестов.

### Key Points
- Промпты — это код и артефакты конфигурации, требующие версионирования.
- Фиксируйте prompt_version в логах и аналитике каждого ответа.
- Сравнение промптов должно опираться на измеримые метрики тестового датасета.
- Регрессионное тестирование промптов предотвращает деградацию сценариев.

### Life Analogy
Выпуск новой редакции школьного учебника. Нельзя просто переписать главу в одном экземпляре книги — нужно зафиксировать номер издания, провести рецензирование и убедиться, что школьники правильно решают контрольные задачи по новому тексту.
