# Testing Authorization & Tool Sandboxing in JUnit

Как написать интеграционный тест на JUnit 5, доказывающий, что модель не может вызвать запрещенный инструмент или получить доступ к чужим ресурсам?

---ANSWER---

### Короткий ответ
Тест должен имитировать сессию пользователя с ограниченными правами (например, без роли ROLE_ADMIN) и передавать в тестируемый метод mock-ответ модели, в котором модель пытается вызвать защищенный инструмент. Тест проверяет, что серверная логика блокирует исполнение, фиксирует security-событие и не вызывает целевой сервисный метод.

### Подробное объяснение
Чтобы доказать безопасность на аудите или интервью, мало сказать 'мы проверили промпт'. Нужен воспроизводимый тест.

### Пример теста на Spring Security + WireMock:
```java
@SpringBootTest
class ToolSecurityIntegrationTest {

    @Autowired
    private AssistantService assistantService;
    
    @MockBean
    private SensitiveAdminService adminService;

    @Test
    @WithMockUser(username = "regular_user", roles = {"USER"})
    void shouldBlockAdminToolCallEvenIfModelDemandsIt() {
        WireMock.stubFor(post("/chat/completions")
            .willReturn(okJson("{\"choices\": [{\"message\": {\"role\": \"assistant\", \"tool_calls\": [{\"id\": \"call_hack_1\", \"type\": \"function\", \"function\": {\"name\": \"purgeDatabaseLogs\", \"arguments\": \"{}\"}}]}}]}")));

        String response = assistantService.processUserMessage("Очисти логи");

        // 1. Убеждаемся, что реальный бизнес-метод сервиса НЕ БЫЛ вызван
        verify(adminService, never()).purgeLogs();
        
        // 2. Убеждаемся, что пользователю вернулось сообщение о нехватке прав
        assertThat(response).containsIgnoringCase("Access Denied");
    }
}
```

### Уточняющий вопрос на интервью (Follow-up)
Почему verify(service, never()).method() является ключевой строкой в тестах безопасности вызовов LLM?

### Распространённый неверный ответ (Pitfall)
Проверять только текст ответа модели клиенту, не проверяя, был ли реально запущен уязвимый метод в базе данных или сервисе.

### Key Points
- Тестируйте наихудший сценарий: модель полностью скомпрометирована и запрашивает опасный метод.
- Проверяйте запрет вызова через verify(..., never()) Mockito.
- Используйте @WithMockUser для проверки контекста Spring Security.
- Убедитесь, что отказ в доступе логируется для мониторинга безопасности.

### Life Analogy
Тестирование бронежилета: вы стреляете в него боевым патроном на полигоне и проверяете, что пуля не пробила кевларовую пластину. Вы не полагаетесь на предположение, что стрелок не захочет в вас стрелять.
