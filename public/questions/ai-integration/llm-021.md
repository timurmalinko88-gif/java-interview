# Testing Pyramid for LLM Applications: Unit, WireMock & Live

Как устроена пирамида тестирования приложений с LLM? В чем различия между Unit-тестами, тестами с WireMock и Live Evaluations с реальным API?

---ANSWER---

### Короткий ответ
Пирамида состоит из трех уровней: 1) Unit-тесты проверяют парсинг DTO, валидацию схем и логику реестра инструментов без сети. 2) Интеграционные тесты с WireMock эмулируют HTTP-ответы LLM-провайдера (включая 429, 500, битый JSON, tool calls), работают детерминированно, быстро и бесплатно в CI/CD. 3) Live Evaluations запускаются отдельно по флагу с реальным API-ключом для оценки поведения вероятностной модели.

### Подробное объяснение
Критическая ошибка — вызывать реальный OpenAI API во время каждого коммита в pull request. Это приводит к нестабильным тестам (flaky tests), тратам бюджета компании и падениям сборки при сетевых сбоях.

### 1. Unit Tests (JUnit 5 + Mockito):
- Тестирование локальных классов инструментов (ServiceStatusToolTest).
- Тестирование санитизации входных строк и извлечения параметров.
- Скорость: миллисекунды. Затраты: $0.

### 2. Integration HTTP Mock Tests (WireMock):
- Поднимается легковесный HTTP-сервер WireMockServer.
- Проверяются таймауты, заголовки авторизации, реакция на Retry-After: 5, корректность сборки тела запроса.
- Скорость: ~1 секунда. Затраты: $0. Детерминированность: 100%.

### 3. Live Model Evaluations:
- Запускаются вручную или по ночному расписанию через профиль Maven: mvn test -Plive-eval -DLLM_API_KEY=...
- Проверяют реальную способность модели следовать системному промпту и выбирать инструменты.
- Без указания ключа сборка проекта проходит успешно и не тратит деньги.

### Уточняющий вопрос на интервью (Follow-up)
Как в Spring Boot интеграционном тесте переключить base URL клиента с боевого API OpenAI на локальный порт WireMock?

### Распространённый неверный ответ (Pitfall)
Зашивать реальный API-ключ в unit-тесты и тратить деньги компании на каждом локальном билде разработчика.

### Key Points
- Никогда не дергайте платный LLM API в обычных CI/CD unit-тестах.
- WireMock — главный инструмент для проверки устойчивости сетевого клиента.
- Проверяйте эмуляцию 429, таймаутов и битого JSON через мок-ответы.
- Live-тесты изолируются под отдельный запуск с проверкой наличия ключа.

### Life Analogy
Подготовка пилота: тренажер в классе (Unit-тесты) -> полет на компьютерном авиасимуляторе со смоделированными отказами двигателей (WireMock) -> реальный тестовый полет на настоящем самолете с инструктором (Live Eval).
