# Why LLMs Never Execute Java Code & Sandbox Principles

Почему языковая модель принципиально не исполняет Java-методы напрямую? Как организовать строгий allowlist инструментов на стороне Spring Boot?

---ANSWER---

### Короткий ответ
LLM — это вероятностная нейросетевая модель, работающая в закрытом облаке провайдера. Она физически изолирована от JVM клиента. Backend обязан использовать строгий Allowlist (реестр зарегистрированных бинов) и ни в коем случае не использовать произвольный динамический вызов методов через неконтролируемую Java Reflection.

### Подробное объяснение
Опасный антипаттерн в архитектуре ассистентов — наивная реализация, когда имя инструмента передается в рефлексию:
```java
// КАТЕГОРИЧЕСКИ ЗАПРЕЩЕНО: Уязвимость Remote Code Execution (RCE)
Method method = this.getClass().getMethod(toolCall.getName(), String.class);
method.invoke(this, toolCall.getArguments());
```
Если модель под воздействием промпт-инъекции запросит инструмент deleteUserData или внутренний геттер, злоумышленник скомпрометирует систему.

### Безопасный паттерн Tool Registry:
Инструменты регистрируются явно как реализации функционального интерфейса в безопасном словаре (Map):

```java
public interface AssistantTool {
    String getName();
    String getDescription();
    Map<String, Object> getJsonSchema();
    String execute(String jsonArgs, SecurityContext context);
}

@Component
public class ToolRegistry {
    private final Map<String, AssistantTool> tools = new ConcurrentHashMap<>();

    public ToolRegistry(List<AssistantTool> toolBeans) {
        for (AssistantTool tool : toolBeans) {
            tools.put(tool.getName(), tool);
        }
    }

    public String executeTool(String name, String jsonArgs, SecurityContext context) {
        AssistantTool tool = tools.get(name);
        if (tool == null) {
            return "{"error": "Unknown tool: " + name + ". Available tools: " + tools.keySet() + ""}";
        }
        return tool.execute(jsonArgs, context);
    }
}
```

### Уточняющий вопрос на интервью (Follow-up)
Как сообщить модели, что запрошенный ею инструмент не существует, не роняя при этом HTTP-запрос пользователя с ошибкой 500?

### Распространённый неверный ответ (Pitfall)
Использовать Java Reflection по переданному из JSON имени класса/метода без проверки в статическом белом списке разрешенных инструментов.

### Key Points
- Модель не имеет прямого доступа к памяти JVM и рантайму Java.
- Динамический вызов через рефлексию по имени от модели — критическая RCE-уязвимость.
- Используйте паттерн Tool Registry с жестким списком разрешенных синглтонов.
- Ошибка отсутствия инструмента возвращается модели в tool сообщении для самокоррекции.

### Life Analogy
Официант в ресторане принимает от посетителя карточку заказа. Если посетитель написал на салфетке 'принесите мне ключ от сейфа ресторана', официант не идет открывать сейф, а сверяет запись с меню и отвечает: 'Этого блюда нет в меню'.
