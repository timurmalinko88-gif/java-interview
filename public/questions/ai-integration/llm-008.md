# Safe Logging and Secret Masking for LLM Integrations

Как организовать безопасное логирование вызовов LLM API в Spring Boot? Какие данные категорически запрещено логировать по умолчанию?

---ANSWER---

### Короткий ответ
Категорически запрещено логировать: API-ключи провайдера (Authorization header), полные промпты пользователей и персональные данные (PII) без маскирования. Логировать следует метаданные: requestId, latency, modelId, HTTP status, количество потраченных токенов (prompt/completion tokens) и код ошибки при сбоях.

### Подробное объяснение
Типичная ошибка при отладке — включение полного логирования HTTP-клиента (level: DEBUG в HttpClient/OkHttp), из-за чего в ELK/Splunk утекают секретные ключи и персональные данные клиентов.

### Угрозы небезопасного логирования:
1. **Утечка API-ключей**: попадание заголовка Authorization: Bearer sk-... в централизованные логи дает доступ к счету компании любому аналитику с доступом к Kibana.
2. **Утечка PII / GDPR / 152-ФЗ**: пользователи могут писать в чат паспортные данные, номера счетов и медицинские симптомы.
3. **Раздувание объема логов**: отправка 50k токенов контекста в каждой строке лога быстро забьет диск и индексы Elasticsearch.

### Правильный логгер-интерцептор:
```java
@Slf4j
public class SafeLlmLoggingInterceptor {

    public void logLlmCall(String model, int promptLen, int statusCode, Duration latency, UsageDto usage) {
        log.info("LLM Call Finished: model={}, promptLengthChars={}, status={}, latencyMs={}, promptTokens={}, completionTokens={}",
                model,
                promptLen,
                statusCode,
                latency.toMillis(),
                usage != null ? usage.promptTokens() : 0,
                usage != null ? usage.completionTokens() : 0
        );
    }

    public static String maskApiKey(String rawKey) {
        if (rawKey == null || rawKey.length() < 8) return "******";
        return rawKey.substring(0, 3) + "..." + rawKey.substring(rawKey.length() - 4);
    }
}
```

### Уточняющий вопрос на интервью (Follow-up)
Как вы организуете трассировку полного тела промпта для отладки в среде разработки (dev/staging), не рискуя включить ее в production?

### Распространённый неверный ответ (Pitfall)
Логировать полный curl-запрос с Authorization: Bearer в System.out или log.info для удобства отладки.

### Key Points
- Никогда не логировать заголовок Authorization и полный API-ключ.
- Промпты пользователей могут содержать PII и не должны писаться в info-логи.
- Логируйте структурированные метрики: tokens, latency, status, correlationId.
- Используйте маскирование секретов и Spring Profiles для безопасного dev-режима.

### Life Analogy
В банковской квитанции банкомат печатает номер карты как '**** **** **** 1234' и никогда не пишет ваш PIN-код. Точно так же логи приложения должны фиксировать факт операции и статус, но маскировать секреты.
