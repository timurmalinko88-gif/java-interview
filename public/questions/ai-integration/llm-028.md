# Framework Tradeoffs: Bare HTTP vs Spring AI vs LangChain4j vs MCP

Как аргументированно выбрать между чистым Java HttpClient, фреймворками Spring AI / LangChain4j и протоколом Model Context Protocol (MCP) при проектировании архитектуры?

---ANSWER---

### Короткий ответ
Чистый HttpClient выбирают для максимальной прозрачности, минимальных зависимостей и полного контроля сетевого уровня. Spring AI идеален для стандартных enterprise-сервисов в экосистеме Spring Boot. LangChain4j подходит для сложных агентских графов и multi-model пайплайнов. MCP (Model Context Protocol) используется для стандартизированного межпроцессного подключения внешних инструментов и контекста.

### Подробное объяснение
Выбор технологического стека должен основываться на требованиях проекта, а не хайпе:

### 1. Чистый Java HttpClient (или Spring RestClient):
- **Плюсы**: Нет сторонних быстро ломающихся зависимостей, 100% прозрачность заголовков и ошибок, легковесный jar, нулевые риски лицензирования.
- **Минусы**: Всю оркестрацию цикла tool calling, retry и парсинг JSON-схем приходится писать вручную (около 300-500 строк качественного кода).
- **Когда применять**: Критичные production-сервисы с жесткими требованиями к безопасности и аудиту.

### 2. Spring AI:
- **Плюсы**: Идеальная интеграция с application.yml, Spring Boot Starters, ChatClient, поддержка Vector Stores (PgVector, Redis).
- **Минусы**: Быстро меняющийся API (версии 1.x), абстракции могут скрывать важные параметры низкоуровневого протокола.
- **Когда применять**: Классические корпоративные микросервисы на Spring Boot 3.x.

### 3. LangChain4j:
- **Плюсы**: Независим от Spring, богатейший набор готовых интеграций, мощные абстракции для агентов, памяти диалога и advanced RAG.
- **Минусы**: Частые мажорные обновления, большой размер зависимостей.
- **Когда применять**: Автономные агенты со сложным ветвлением логики и RAG-пайплайнами.

### 4. Model Context Protocol (MCP):
- **Что решает**: Открытый стандарт от Anthropic, разделяющий клиенты и серверы контекста по протоколу JSON-RPC (через stdio или SSE).
- **Когда применять**: Когда нужно предоставить общий набор инструментов разным клиентам (IDE, локальным ассистентам и бэкендам).

### Уточняющий вопрос на интервью (Follow-up)
В какой момент проекту становится выгоднее перейти с рукописного HTTP-клиента на Spring AI или LangChain4j?

### Распространённый неверный ответ (Pitfall)
Подключать тяжелый AI-фреймворк с десятками транзитивных зависимостей ради одного простого chat-эндпоинта без инструментов и RAG.

### Key Points
- Чистый HTTP-клиент дает максимальный контроль и прозрачность протокола.
- Spring AI естественен для Spring Boot инфраструктуры и стандартного RAG.
- LangChain4j мощнее в сложных агентских и мультимодельных сценариях.
- MCP стандартизирует подключение инструментов между процессами через JSON-RPC.

### Life Analogy
Чистый HttpClient — это сборка велосипеда своими руками из фирменных деталей (знаешь каждый винтик). Spring AI — это покупка городского велосипеда в официальном дилерском салоне. MCP — это международный стандарт рельсов, по которым могут ходить любые поезда.
