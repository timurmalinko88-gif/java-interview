# Engineering High-Precision Tool Descriptions

Как описания инструментов (Tool Descriptions) и JSON Schema влияют на точность выбора инструментов моделью? Как предотвратить вызов не того инструмента при неоднозначном запросе?

---ANSWER---

### Короткий ответ
Модель выбирает инструмент исключительно по его имени, описанию (description) и описанию параметров в JSON Schema. Описание должно содержать четкие условия 'когда использовать', 'когда НЕ использовать' и формат параметров. При неоднозначности запрос должен побуждать модель задать уточняющий вопрос пользователю, а не вызывать случайный инструмент.

### Подробное объяснение
Если у вас зарегистрировано 10 инструментов, модель может путаться между похожими функциями: например, getServiceStatus и getTicketDetails.

### Пример плохого описания:
```json
{
  "name": "checkStatus",
  "description": "Checks status"
}
```
*Результат*: Модель будет вызывать эту функцию при любых словах 'как дела', 'какой статус у тикета', 'работает ли сервер'.

### Пример высокоточного описания (High-Precision):
```json
{
  "name": "getServiceStatus",
  "description": "Returns operational health and latency for internal infrastructure services. USE ONLY when user specifically asks about system components like 'auth', 'payment', 'database', 'notification'. DO NOT use for user support tickets or order status. If service name is not mentioned, ask user for clarification first.",
  "parameters": {
    "type": "object",
    "properties": {
      "serviceName": {
        "type": "string",
        "enum": ["auth", "payment", "database", "notification", "storage"],
        "description": "Exact service identifier from the allowed list"
      }
    },
    "required": ["serviceName"]
  }
}
```

### Приемы устранения неоднозначности:
1. Явные негативные правила (DO NOT USE FOR...).
2. Применение enum для параметров с фиксированным набором допустимых значений.
3. Инструкция в системном промпте: *'Если пользовательский запрос неоднозначен или не содержит нужных параметров, НЕ вызывай инструменты наугад — задай уточняющий вопрос'*.

### Уточняющий вопрос на интервью (Follow-up)
Что произойдет с точностью выбора инструментов, если зарегистрировать в контексте 50 инструментов одновременно?

### Распространённый неверный ответ (Pitfall)
Оставлять поле description пустым или писать односложные фразы вроде 'получает данные', перекладывая логику выбора на догадки модели.

### Key Points
- Описание инструмента — это инструкция маршрутизации для модели.
- Включайте в описание явные критерии: когда вызывать и когда категорически избегать.
- Используйте enum и подробные пояснения к каждому параметру в схеме.
- Инструктируйте модель задавать уточняющие вопросы при нехватке параметров.

### Life Analogy
Если на двух кнопках в кабине лифта написать просто 'Ехать', пассажир растеряется. Если написать 'Вверх (жилые этажи 1-10)' и 'Вниз (парковка и склад)', ошибка исключена.
