# Prompting vs RAG vs Fine-Tuning Decision Framework

Как архитектор Java-решений выбирает между Prompt Engineering, RAG (Retrieval-Augmented Generation) и Fine-Tuning для решения прикладной задачи?

---ANSWER---

### Короткий ответ
Prompt Engineering используется, когда задача решается общими знаниями модели и четкими инструкциями. RAG необходим при работе с динамическими, приватными или часто меняющимися корпоративными данными (БД, документация). Fine-Tuning оправдан для изменения стиля, формата или узкоспециализированного тона, но не для внедрения фактологических знаний.

### Подробное объяснение
Выбор архитектурного подхода определяет стоимость, сложность и надежность системы:

| Критерий | Prompt Engineering | RAG (Retrieval-Augmented) | Fine-Tuning |
|---|---|---|---|
| Источник знаний | Встроенные знания модели | Внешняя БД / Vector Store / REST | Веса модели |
| Актуальность данных | На дату обучения модели | Реальное время (Real-time) | На дату тюнинга |
| Галлюцинации | Высокий риск | Низкий (строго по источникам) | Средний |
| Стоимость внедрения | Минимальная ($0) | Средняя (индексация, векторная БД) | Высокая (GPU, датасет) |
| Прозрачность/Аудит | Низкая | Высокая (ссылки на документы) | Черный ящик |

### Архитектурное правило:
1. Начинать **всегда** с Prompt Engineering (few-shot examples, structured output).
2. Если нужны актуальные корпоративные знания (статьи поддержки, тикеты клиентов, остатки на складе) — реализовывать **RAG или Tool Calling**.
3. Fine-Tuning применять только в исключительных случаях (например, строгий юридический стиль ответов или сжатие весов для локального Ollama инференса).

### Уточняющий вопрос на интервью (Follow-up)
Почему fine-tuning считается плохим выбором для добавления в модель постоянно обновляющегося каталога товаров интернет-магазина?

### Распространённый неверный ответ (Pitfall)
Предлагать дообучение (Fine-Tuning) базовой модели каждый раз, когда меняются цены или регламенты в компании, вместо RAG или вызова API.

### Key Points
- Prompting — быстрый старт с минимальными затратами.
- RAG — стандарт для динамических фактов и приватных данных компании.
- Fine-Tuning обучает форме, стилю и специфическому синтаксису, а не фактам.
- В RAG каждый ответ можно снабдить точной ссылкой на источник (grounding).

### Life Analogy
Prompting — это дать умному стажеру четкую памятку перед сменой. RAG — это посадить стажера перед актуальной базой знаний и поисковиком. Fine-Tuning — это отправить стажера на полугодовые курсы переквалификации.
