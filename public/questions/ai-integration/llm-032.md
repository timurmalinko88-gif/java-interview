# Planning Mode, Subagents & Artifacts Orchestration

Как устроены режимы Planning Mode, система Артефактов (Artifacts) и параллельные субагенты (Subagents) в Google Antigravity при решении масштабных инженерных задач?

---ANSWER---

### Короткий ответ
Planning Mode предотвращает необдуманные изменения: агент исследует кодовую базу в режиме read-only, формирует implementation_plan.md и останавливается до одобрения пользователем. Субагенты (invoke_subagent) позволяют распараллеливать независимые задачи (исследования, рефакторинг). Артефакты служат постоянными структурированными документами для взаимодействия с пользователем.

### Подробное объяснение
При сложных рефакторингах или добавлении больших фичей типичный AI-ассистент начинает спешно менять файлы, ломая архитектуру. В Google Antigravity встроен защитный фреймворк инженерной дисциплины:

### 1. Planning Mode (Режим планирования):
- **Фаза исследования (Research)**: Агент выполняет grep, поиск файлов, чтение спецификаций и кодовой базы БЕЗ модификации исходников.
- **Фаза плана (Implementation Plan)**: Создается артефакт implementation_plan.md с описанием архитектуры, файлов (NEW, MODIFY, DELETE), открытых вопросов и плана верификации.
- **Human Gate (Точка контроля)**: Агент ОБЯЗАН остановиться и дождаться явного подтверждения пользователя перед написанием кода.
- **Фаза верификации (Walkthrough)**: После выполнения работ формируется walkthrough.md с доказательствами работоспособности (логи тестов, скриншоты).

### 2. Multi-Agent Orchestration (Субагенты):
- Команда `invoke_subagent`: запуск независимых процессов агента с собственной изолированной памятью.
- Специфические роли: `research` (исследователь кодовой базы), `tester` (запуск тестов), параллельные агенты для независимых подзадач.
- Асинхронное пробуждение (Reactive Wakeup): родительский агент не висит в бесконечном цикле опроса, а просыпается автоматически при завершении работы субагента.

### 3. Artifacts (Система артефактов):
- Структурированные Markdown-документы с интерактивными Mermaid-диаграммами, алертами (IMPORTANT, TIP, WARNING) и кликабельными ссылками на файлы.

### Уточняющий вопрос на интервью (Follow-up)
Почему отделение фазы исследования от фазы изменения кода кардинально снижает риск деградации архитектуры проекта?

### Распространённый неверный ответ (Pitfall)
Игнорировать Planning Mode при масштабных задачах и позволять модели сразу переписывать ключевые классы проекта без предварительного плана.

### Key Points
- Planning Mode разделяет исследование, утверждение плана, исполнение и верификацию.
- План в implementation_plan.md согласуется с разработчиком перед первой строкой кода.
- Субагенты распараллеливают тяжелые исследовательские задачи без засорения контекста.
- Артефакты служат единым источником правды о текущем состоянии фичи.

### Life Analogy
Строительство дома: сначала геодезическая разведка и чертеж архитектора с визой заказчика (Planning Mode + implementation_plan.md), затем специализированные бригады электриков и каменщиков (Subagents), и лишь в конце — сдача объекта по акту приемки (walkthrough.md).
